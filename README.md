# רשימת קניות

אפליקציית ווב (PWA) בעברית לניהול רשימות קניות בנטו חיסכון וביש חסד.

## פיתוח

```bash
npm install
npm run dev      # שרת פיתוח
npm run build    # בנייה לתיקיית dist
```

## התקנה בטלפון

האפליקציה מתפרסמת אוטומטית ל-GitHub Pages בכל push (ראו `.github/workflows/deploy.yml`).
פותחים את הכתובת בטלפון ובוחרים "הוספה למסך הבית" (באייפון: שיתוף ← הוספה למסך הבית).

כל הנתונים נשמרים במכשיר (IndexedDB). כל שעה נשמר גיבוי אוטומטי במכשיר, ובמסך ההגדרות אפשר לייצא לאקסל
(כולל הורדה אוטומטית כל שעה כשהאפליקציה פתוחה) ולשחזר מקובץ האקסל.

## רשימה משותפת (Firebase)

הסנכרון בין טלפונים עובד מול פרויקט Firebase של המשתמש. ההוראות להגדרה מופיעות במסך ההגדרות.
כללי האבטחה של Firestore (מוצגים גם באפליקציה) מתירים גישה רק למי שמחזיק בקוד המשפחתי:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /families/{code}/{col}/{docId} {
      allow read, write: if code.size() >= 20;
    }
  }
}
```

בדיקה מקומית מול האמולטור: `http://localhost:4173/?firestoreEmulator=127.0.0.1:8085`.

## המטבח שלי (`/kitchen/`)

אפליקציה שנייה באותו אתר: סרטונים, מתכונים ותכנון שולחן שבת וחג. נפתחת בכתובת האתר + `kitchen/`
(למשל `https://<user>.github.io/shopping-list/kitchen/`), וגם אותה אפשר להוסיף למסך הבית.
הקוד נמצא ב-`kitchen/src`, והנתונים נשמרים במכשיר (IndexedDB) בנפרד מרשימת הקניות. גיבוי ושחזור — במסך ההגדרות.

- שם הסרטון ותמונת הכותרת נמשכים מיוטיוב בלי מפתח (oEmbed).
- משיכה אוטומטית של תיאור הסרטון (ממנו נבנה המתכון) דורשת מפתח YouTube Data API חינמי; בלי מפתח מדביקים את התיאור ידנית.
- המתכון נבנה רק ממה שכתוב בתיאור. אם אין בו מצרכים ושלבי הכנה, המתכון מסומן "חסר".

## כדורגל 3D (`/football/`)

אפליקציה שלישית באותו אתר: משחק כדורגל תלת-ממדי בדפדפן (Three.js), בכתובת האתר + `football/`.
הקוד נמצא ב-`football/src`. כל הקבוצות והשחקנים בדיוניים, והכול רץ במכשיר (בלי שרת).

- **מנוע פיזיקה** (`physics.ts`): הכדור הוא גוף עצמאי – כבידה, גרר אוויר, אפקט מגנוס (כדור מסובב מתעקם), ניתורים
  עם חיכוך וספין, קורות ומשקוף, רשת, ושלוליות בגשם. שחקנים מתנגשים לפי מסה וכוח (מאבקי כתף).
- **אנימציה** (`playerModel.ts`): שחקן מפרקי עם אנימציה פרוצדורלית – מחזור ריצה לפי מהירות, הטיה בפניות, בעיטה,
  נגיחה, תיקול, גלישה, זינוק שוער וחגיגות. תנועה עם אינרציה: תאוצה, בלימה וזריזות לפי נתוני השחקן.
- **שליטה** (`input.ts`): מקלדת, שלט (מיפוי קונסולה סטנדרטי) ומסך מגע. מסירה/הגבהה/עומק/בעיטה עם מד עוצמה,
  סיום מתוזמן, פינס וצ'יפ, כדרור צמוד, מהלכי כדרור, ג'וקי, תיקול עומד וגלישה, לחץ של חבר קבוצה והחלפת שחקן.
- **חוקים** (`match.ts`): נבדל, חוץ, קרן, בעיטת שער, עבירות, כרטיסים, נגיעות יד, בעיטות חופשיות עם חומה
  וקו מסלול, פנדלים עם מעגל ריכוז, דו-קרב פנדלים, מחציות ותוספת זמן, הילוך חוזר לשערים.
- **בינה מלאכותית** (`ai.ts`): מערכים, 5 סגנונות טקטיים (לחץ גבוה, טיקי-טאקה, חניית אוטובוס, מתפרצת, מאוזן),
  לחץ, שמירה אזורית/אישית, קו נבדלים, ריצות עומק/חיתוך/תמיכה, החלטות של מחזיק הכדור, ושוערים (מיקום, תגובה,
  זינוק, תפיסה/הדפה, יציאה ל-1 על 1 ולכדורי רוחב).
- **אצטדיון** (`stadium.ts`): דשא עם פסי כיסוח שנשחק במהלך המשחק, קהל מונפש, שלטי פרסומת, זרקורים,
  שעות יום/בין ערביים/לילה ומזג אוויר (גשם, שלג – עם קווים כחולים וכדור כתום).
- **מצבי משחק** (`modes.ts`): משחק מהיר (כולל שני שחקנים), טורניר נוקאאוט, קריירת מנג'ר (תקציב, העברות, סקאוטינג,
  מורל, מסיבות עיתונאים), קריירת שחקן (יעדים, אימונים, חוזים ולייף סטייל) וקבוצת חלומות (מארזים, כימיה, שוק העברות,
  ליגת יריבויות ואלופים מול יריבים וירטואליים). ההתקדמות נשמרת ב-localStorage.

- **שיפוט ו-VAR**: לכל שופט אופי (קפדן / מקל / שולף כרטיסים) שמשפיע על כרטיסים ויתרון; שופטים מפספסים לפעמים נבדל צמוד,
  וה-VAR בודק שערים ופנדלים גבוליים עם קווי נבדל וירטואליים ומסך בצד המגרש.
- **כושר, פציעות וחילופים**: עייפות מתחת ל-20% פוגעת במהירות, בתיקולים ובדיוק; פציעות (ירך, קרסול, ברך, ראש עם חבישה),
  חילופים מתפריט ההשהיה וחילופי מחשב. בקריירה הכושר, הפציעות והמורל עוברים בין משחקים.
- **לחץ**: בדקות האחרונות של משחק צמוד, שחקנים עם קור רוח נמוך מאבדים דיוק.
- **מקשים**: יהלום בסגנון נינטנדו סוויץ' – ל (K) הגבהה / החלפת שחקן, ם (O) הגנה על הכדור / ג'וקי, ף (;) בעיטה / תיקול,
  ך (L) מסירה / לחץ חבר; ן (I) מסירת עומק. ↑+ף בננה, ↓+ף פצצה, חצים+ף בהגנה = חמש עבירות שונות.
  עכבר: קליק שמאלי מכוון, קליק ימני הטעיית בעיטה / הקפצה, תזוזה מהירה = מהלך כדרור. T = חילוף מהיר.
- **מצלמה וקו עזר**: המצלמה ממסגרת גם את הכדור וגם את השחקן שלך; בזמן טעינת בעיטה/הגבהה מוצג מסלול הכדור הצפוי.
- **דמות תלת-ממדית משלך** (`skinnedModel.ts`): בהגדרות אפשר לטעון קובץ GLB עם שלד (Mixamo, Valve Biped או Blender .L/.R).
  הגוף הפרוצדורלי ממשיך לרוץ כ"שלד מניע" בלתי נראה וכל עצם במודל מעתיקה את הסיבוב שלו, כך שכל האנימציות (ריצה, בעיטות,
  צניחות, חגיגות, הילוך חוזר) עובדות. המדים נצבעים בצבעי הקבוצה ומספר מודבק על הגב. הקובץ נשמר רק ב-IndexedDB של הדפדפן.
- **Foot IK** (`reachFoot` ב-`playerModel.ts`): פותר IK של שתי עצמות (ירך-ברך) שמכופף את הרגל אל הפנים הקרובות של הכדור
  בכל נגיעה בכדרור, עצירה, מסירה, בעיטה וסקיל. כשהכדור רחוק מצעד – האגן נשלח קדימה ושוקע. מסירות קצרות בפנים כף הרגל
  (הרגל מסתובבת החוצה), הנפה אחורה וסיום תנועה לפי עוצמת הבעיטה, הטיית גו לאחור בהגבהה, ראש שעוקב אחרי הכדור,
  ומעידה (נאבק על שיווי משקל) במקום נפילה בחלק מהמגעים.
- **ריאליזם נוסף**: שופט פיזי על המגרש, בוץ והחלקות באזורים שחוקים, רוח, מומנטום, מצב פאניקה בדקות האחרונות,
  יתרון שחוזר לעבירה, נגיעות יד מכוונות מול מקריות, מאמנים מגיבים, ויכוחים אחרי שריקה, הילוך חוזר סופר-איטי,
  השעיות וערעורים, פייר-פליי פיננסי, שערוריות מחוץ למגרש, מלחמות פסיכולוגיות ומערך נפרד בלי כדור.

בדיקה אוטומטית: `football/?debug` חושף את המשחק הרץ (`window.__fb`) כדי שבדיקות יוכלו להריץ אותו מהר.
