פרק 17 · לשמור מידע, לשאול עליו שאלות, ולא לאבד אותו

מסדי נתונים ו-SQL

כל אפליקציה, מאינסטגרם ועד טבלת השיאים במשחק שלך, שומרת מידע. בפרק הזה תכתוב שאילתות אמיתיות למסד נתונים.

למה לא פשוט לשמור בקובץ?

אפשר לשמור מידע בקובץ טקסט. אבל מה קורה כשיש 100 מיליון משתמשים? כשאלף אנשים כותבים באותה שנייה? כשצריך למצוא ״כל השחקנים מחיפה עם ניקוד מעל 1000״? קובץ לא יודע לעשות את זה מהר ובבטחה. Database (מסד נתונים) הוא תוכנה שנבנתה בדיוק לזה: שמירה מסודרת, חיפוש מהיר (בעזרת אינדקסים, כמו האינדקס של גוגל), עבודה של הרבה משתמשים במקביל, וגיבויים.

טבלאות, שורות ועמודות

במסד נתונים טבלאי (רלציוני), המידע יושב בטבלאות, כמו גיליון אקסל:

  • כל טבלה מתארת סוג אחד של דבר: players, items, matches.
  • כל שורה (row) היא פריט אחד: שחקן אחד.
  • כל עמודה (column) היא תכונה: שם, גיל, עיר, ניקוד.
  • לכל שורה יש מזהה ייחודי שנקרא Primary Key (מפתח ראשי), בדרך כלל עמודת id. שני שחקנים יכולים להיקרא ״נועה״, אבל לכל אחת id אחר.

SQL: לשאול שאלות

SQL היא שפה ״הצהרתית״: אתה לא אומר למחשב איך למצוא, רק מה אתה רוצה. ״תן לי את השמות והניקוד של 3 השחקנים הכי טובים״ נכתב כמעט כמו באנגלית:

SELECT name, score        -- אילו עמודות
FROM players               -- מאיזו טבלה
WHERE age >= 13           -- סינון (לא חובה)
ORDER BY score DESC       -- מיון מהגבוה לנמוך
LIMIT 3;                  -- רק 3 תוצאות

נסה בעצמך! יש כאן מסד נתונים קטן עם 10 שחקנים. לחץ על הדוגמאות, ואז שנה אותן וכתוב שאילתות משלך:

אתגרים ל-SQL
  1. מצא את כל השחקנים מתל אביב.
  2. מצא את השחקן הצעיר ביותר (רמז: ORDER BY age ו-LIMIT 1).
  3. כמה שחקנים משחקים Fortnite?
  4. מה הניקוד הגבוה ביותר מבין שחקני Minecraft? (רמז: MAX)
  5. אילו שחקנים בני 14 עם ניקוד מעל 900?

לשנות מידע

חוץ מ-SELECT (לקרוא), יש עוד שלוש פקודות בסיסיות. ביחד קוראים להן CRUD: Create (צור), Read (קרא), Update (עדכן), Delete (מחק). כמעט כל אפליקציה בעולם היא בעצם ״CRUD עם עיצוב יפה״.

INSERT INTO players (name, age, city, game, score)       -- צור
VALUES ('גיא', 15, 'נתניה', 'GTA', 0);

UPDATE players SET score = score + 50 WHERE id = 4;     -- עדכן

DELETE FROM players WHERE id = 6;                        -- מחק
הפקודה הכי מסוכנת בעולם

DELETE FROM players; בלי WHERE מוחקת את כל הטבלה. מתכנתים ותיקים מספרים על זה סיפורי אימה. בגלל זה עושים גיבויים, ועובדים על עותק ״לבדיקות״ לפני שנוגעים במידע האמיתי.

קשרים בין טבלאות

הכוח האמיתי של מסד רלציוני הוא קשרים. במקום לכתוב את כל פרטי השחקן בכל פעם שהוא קונה פריט, יש טבלת purchases עם עמודה player_id שמצביעה על השחקן. עמודה כזאת נקראת Foreign Key (מפתח זר). פקודת JOIN מחברת טבלאות ביחד:

SELECT players.name, items.title, purchases.price
FROM purchases
JOIN players ON purchases.player_id = players.id
JOIN items   ON purchases.item_id   = items.id;

אגב, SQLite הוא מסד נתונים זעיר שיושב בתוך קובץ אחד, והוא כנראה התוכנה הנפוצה ביותר בעולם: הוא נמצא בכל טלפון, בכל דפדפן ובהרבה משחקים (לשמירת נתונים). ובתוך הדפדפן עצמו יש מסד נתונים בשם IndexedDB, שבו, למשל, אפליקציית רשימת הקניות שהמדריך הזה יושב בתוכה שומרת את הרשימות שלך.

SQL Injection: למה בודקים כל קלט

נניח שאתר בונה שאילתה ככה: "SELECT * FROM users WHERE name = '" + input + "'". מה קורה אם מישהו מקליד בשדה השם: ' OR '1'='1? השאילתה הופכת ל״תן לי את כל המשתמשים״! זו SQL Injection, אחת הפריצות הנפוצות בהיסטוריה. הפתרון: לעולם לא לחבר קלט של משתמש ישירות לשאילתה, אלא להשתמש בשאילתות עם פרמטרים, שהספריות מספקות.
