פרק 9 · לולאת משחק, פיזיקה, התנגשויות ומנועי משחק

איך משחקים עובדים

כל משחק, מטטריס ועד GTA, הוא בעצם אותה תוכנית קטנה שרצה שוב ושוב, 60 פעמים בשנייה.

הלב של כל משחק: לולאת המשחק

סרט הוא רצף של תמונות מוכנות מראש. משחק שונה: הוא מחשב כל תמונה ברגע האחרון, לפי מה שאתה עושה. כדי לעשות את זה, כל משחק מריץ את Game Loop (לולאת המשחק):

1. קלט: מה השחקן לחץ?←2. עדכון: הזז דברים, בדוק התנגשויות, חוקי המשחק←3. ציור: צייר את כל המסך←חזור להתחלה
function gameLoop() {
  readInput();      // מה לחוץ במקלדת/בשלט?
  update();         // הזז שחקן, אויבים, כדורים. בדוק התנגשויות.
  render();         // צייר הכול מחדש
  requestAnimationFrame(gameLoop);   // ובפריים הבא, שוב!
}

כל סיבוב של הלולאה נקרא Frame (פריים, תמונה). כמה פריימים המשחק מספיק לחשב בשנייה נקרא FPS (Frames Per Second, תמונות לשנייה). 30 FPS מרגיש בסדר, 60 FPS מרגיש חלק, ו-120 ומעלה זה למשחקי תחרות. כשאומרים שמשחק ״מגמגם״ או ״לאגי״, הכוונה שה-FPS ירד כי המחשב לא מספיק לחשב הכול בזמן.

תקציב זמן

ב-60 FPS, יש למשחק 16.6 אלפיות שנייה לכל פריים. בזמן הזה הוא צריך לקרוא קלט, להזיז מאות מכוניות והולכי רגל, לחשב פיזיקה, להחליט מה כל דמות עושה, לנגן צלילים ולצייר מיליוני משולשים. זו הסיבה שמתכנתי משחקים אובססיביים למהירות.

זמן בין פריימים (Delta Time)

בעיה: אם תזיז את השחקן 5 פיקסלים בכל פריים, אז במחשב שרץ ב-120 FPS הוא ינוע פי 2 יותר מהר מאשר במחשב שרץ ב-60 FPS. לא הוגן! הפתרון: מודדים כמה זמן עבר מהפריים הקודם, Delta Time (הפרש זמן), ומכפילים בו:

player.x += player.speed * deltaTime;   // מהירות בפיקסלים לשנייה, לא לפריים

פיזיקה בסיסית

לא צריך להיות גאון במתמטיקה. רוב הפיזיקה במשחקים בנויה על שלושה מושגים:

  • מיקום (Position): איפה הדבר נמצא. x ו-y (ובתלת-ממד גם z).
  • מהירות (Velocity): כמה המיקום משתנה בכל שנייה, ולאיזה כיוון.
  • תאוצה (Acceleration): כמה המהירות משתנה. כוח המשיכה (Gravity) הוא תאוצה קבועה כלפי מטה.
// קפיצה במשחק פלטפורמה, בכל פריים:
player.vy += GRAVITY * dt;          // כוח המשיכה מגביר את המהירות למטה
player.y  += player.vy * dt;        // המהירות משנה את המיקום
if (player.y > groundY) {         // נחת על הרצפה
  player.y = groundY;
  player.vy = 0;
}
if (jumpPressed && onGround) player.vy = -JUMP_POWER;   // קפיצה = מהירות כלפי מעלה

זה הכול! ארבע שורות וקיבלת קפיצה שמרגישה אמיתית. במשחקים גדולים משתמשים בPhysics Engine (מנוע פיזיקה) מוכן, שמטפל גם בסיבובים, חיכוך, קפיצות של חפצים והתרסקויות.

התנגשויות

איך המשחק יודע שהכדור פגע באויב? הוא בודק Collision (התנגשות). אבל לבדוק כל פיקסל של דמות זה איטי מדי. לכן לכל דבר יש צורה פשוטה ובלתי נראית מסביבו, Hitbox (תיבת פגיעה): מלבן, עיגול או קופסה. בודקים רק אם הצורות הפשוטות נוגעות:

// שני עיגולים נוגעים אם המרחק בין המרכזים קטן מסכום הרדיוסים
function hit(a, b) {
  const dist = Math.hypot(a.x - b.x, a.y - b.y);   // פיתגורס!
  return dist < a.r + b.r;
}

עכשיו שחק במשחק הבא. הוא בנוי בדיוק מהדברים שלמדת: לולאת משחק, Delta Time, מהירות, התנגשות עיגולים, ו״בינה מלאכותית״ פשוטה של שוטר שנע לכיוון שלך. הדלק את מצב מפתח כדי לראות את ה-Hitbox ואת הווקטורים.

גרפיקה דו-ממדית

במשחקים דו-ממדיים (כמו מריו, סלסט, Hollow Knight), כל דמות היא Sprite (ספרייט): תמונה קטנה. אנימציה נוצרת מכמה ספרייטים שמתחלפים מהר, כמו דפדפת. כל התמונות של הדמות מסודרות בקובץ אחד בשם Sprite Sheet. עולמות בנויים לרוב מאריחים בגודל קבוע, Tilemap (מפת אריחים), כמו לגו. כלים מומלצים לציור פיקסל-ארט: Aseprite, Piskel (חינמי, בדפדפן).

צליל

אל תזלזל בצליל! אפקטים קוליים (SFX) ומוזיקה הם חצי מההרגשה של משחק. יריה בלי ״בום״ מרגישה חלשה. אתרים כמו freesound.org נותנים צלילים חינמיים, jsfxr מייצר אפקטים רטרו בלחיצה, ויש היום כלי AI שיוצרים מוזיקה (בפרק כלי ה-AI).

מנועי משחק

לבנות משחק מאפס (כמו שעשינו במעבדה) זה מצוין ללמידה. אבל למשחקים אמיתיים משתמשים בGame Engine (מנוע משחק): תוכנה שכבר כוללת גרפיקה, פיזיקה, צליל, אנימציה, קלט ועורך ויזואלי לבניית שלבים. אתה מתמקד במה שהופך את המשחק שלך למיוחד.

עיצוב משחקים: מה עושה משחק לכיף

תכנות זה רק חצי. Game Design (עיצוב משחקים) זו האומנות להחליט מה השחקן עושה ולמה זה כיף:

  • לולאת ליבה (Core Loop): הפעולה שחוזרת שוב ושוב. ב-GTA: לקבל משימה ← לנסוע ← לבצע ← לקבל כסף ← לקנות דברים ← משימה גדולה יותר.
  • תחושה (Game Feel, או Juice): רעידת מסך, חלקיקים, צלילים, האטה קטנה כשפוגעים. פרטים קטנים שהופכים פעולה ל״מספקת״.
  • קושי הדרגתי: קל בהתחלה, קשה יותר בהדרגה. לא מתסכל, לא משעמם.
  • משוב: השחקן תמיד צריך להבין מה קרה ולמה.

להתחיל ישר עם ״משחק ענק עם עולם פתוח ומולטיפלייר״. זה לא יסתיים לעולם. מפתחי משחקים מקצועיים מתחילים עם משחקים זעירים: פונג, פלאפי בירד, סנייק. תסיים 5 משחקים קטנים, ותדע יותר מאשר מי שהתחיל משחק ענק אחד ונטש.
