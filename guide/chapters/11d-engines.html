שים לב: בכל המנועים יש פונקציה שרצה בכל פריים ומקבלת את ה-Delta Time. זו בדיוק לולאת המשחק שבנית בעצמך בפרק המשחקים! המנוע פשוט מריץ אותה בשבילך.

ורעיון הComponent (רכיב) הוא אולי הכי חשוב: במקום ליצור ״מחלקת מכונית״ ענקית, בונים אובייקט ומרכיבים עליו חלקים כמו לגו. גוף פיזיקלי + מודל תלת-ממדי + צליל מנוע + סקריפט נהיגה = מכונית. רוצה מכונית משטרה? אותו דבר + סירנה + סקריפט רדיפה.

Unity עם C#

ב-Unity כותבים סקריפטים ב-C#, ״מדביקים״ אותם על אובייקט, והמנוע קורא לפונקציות שלהם. הנה דמות שזזה וקופצת:

using UnityEngine;

public class PlayerController : MonoBehaviour
{
    public float speed = 5f;          // public = אפשר לשנות מהעורך בלי לגעת בקוד!
    public float jumpForce = 7f;
    Rigidbody rb;

    void Start()                       // רץ פעם אחת בהתחלה
    {
        rb = GetComponent<Rigidbody>();   // מצא את רכיב הפיזיקה של האובייקט
    }

    void Update()                      // רץ בכל פריים
    {
        float x = Input.GetAxis("Horizontal");   // חיצים/WASD/ג'ויסטיק: בין -1 ל-1
        float z = Input.GetAxis("Vertical");
        Vector3 move = new Vector3(x, 0, z) * speed * Time.deltaTime;
        transform.Translate(move);

        if (Input.GetButtonDown("Jump"))
            rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse);
    }

    void OnTriggerEnter(Collider other)   // המנוע קורא לזה כשנכנסים לטריגר
    {
        if (other.CompareTag("Coin"))
            Destroy(other.gameObject);
    }
}

C# דומה מאוד ל-JavaScript, עם הבדל חשוב אחד: צריך לכתוב סוג לכל משתנה (float למספר עשרוני, int לשלם, string לטקסט, bool לאמת/שקר). זה נקרא Static Typing, והוא עוזר למצוא טעויות עוד לפני שמריצים.

Godot עם GDScript

ב-Godot, כל דבר הוא Node (צומת), והצמתים מסודרים בעץ. דמות היא צומת מסוג CharacterBody2D, ומתחתיה צמתים של ספרייט, צורת התנגשות ומצלמה. הקוד כתוב ב-GDScript, שנראה כמעט כמו Python:

extends CharacterBody2D

const SPEED = 200.0
const JUMP_VELOCITY = -400.0
var gravity = 980.0

func _physics_process(delta):                    # רץ בכל פריים פיזיקלי
    if not is_on_floor():
        velocity.y += gravity * delta               # כוח משיכה, בדיוק כמו בפרק הפיזיקה

    if Input.is_action_just_pressed("ui_accept") and is_on_floor():
        velocity.y = JUMP_VELOCITY

    var direction = Input.get_axis("ui_left", "ui_right")
    velocity.x = direction * SPEED

    move_and_slide()                                # המנוע מזיז ומטפל בהתנגשויות

שים לב כמה זה קצר: move_and_slide עושה את כל עבודת ההתנגשויות שבנינו ביד במעבדת ה-Platformer.

Unreal עם Blueprints

ב-Unreal אפשר לתכנת בלי לכתוב אף שורה, בעזרת Blueprints: קוביות (״צמתים״) שמחברים בחוטים. כל קובייה היא פעולה (״הזז״, ״נגן צליל״, ״אם״), והחוטים הלבנים קובעים את הסדר. למשל:

Event: כשנכנסים לאזור←Branch: האם זה השחקן?←Play Sound: ״דינג״←Add Score: 100←Destroy Actor: המטבע

זה בדיוק אותו היגיון כמו קוד: אירוע, תנאי, פעולות. הרבה משחקים מסחריים נבנו בעיקר ב-Blueprints. כשצריך מהירות מקסימלית, כותבים חלקים ב-C++.

היתרון הענק של Roblox: שרתים, מולטיפלייר, שמירת נתונים וקהל של עשרות מיליוני שחקנים ביום, הכול מובנה. בגיל 14 זו אולי הדרך הכי מהירה לבנות משחק שאנשים אמיתיים ישחקו בו.

Blender: ליצור את העולם

כל מנוע צריך תוכן: מודלים, טקסטורות, אנימציות. Blender הוא הכלי החינמי לזה. תהליך העבודה הטיפוסי:

  1. מידול: מתחילים מצורה פשוטה (קובייה) ו״דוחפים ומושכים״ פאות. מקשי הקסם: G להזיז, R לסובב, S להגדיל, E ״לשלוף״ פאה, Tab למעבר בין מצב אובייקט למצב עריכה.
  2. UV ו-טקסטורה: ״פורשים״ את המודל לדף שטוח וצובעים עליו.
  3. ריג ואנימציה: מכניסים שלד ומזיזים אותו לאורך ציר זמן.
  4. ייצוא: שומרים בפורמט .fbx או .glb וגוררים למנוע.
טיפ ל-Low Poly

אל תנסה ליצור מודלים מציאותיים בהתחלה. סגנון Low Poly (מעט משולשים, צבעים שטוחים) קל ללמוד, נראה מעולה, רץ מהר, והרבה משחקי אינדי מצליחים משתמשים בו. מכונית Low Poly לוקחת כמה שעות, לא שבועות.
