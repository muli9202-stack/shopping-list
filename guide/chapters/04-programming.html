פרק 4 · אלגוריתמים, שפות ואיך המחשב מבין אותך

מה זה תכנות

תכנות זה לכתוב הוראות מדויקות מאוד למישהו שמבצע בדיוק את מה שאמרת, ולא את מה שהתכוונת.

המחשב הוא עובד מהיר מאוד וטיפש מאוד

דמיין שאתה צריך להסביר לרובוט איך להכין כריך. אתה אומר ״שים חמאת בוטנים על הלחם״. הרובוט לוקח את כל הצנצנת הסגורה ומניח אותה על כיכר הלחם. טכנית, הוא עשה בדיוק מה שאמרת!

זה מה שזה לתכנת. המחשב לא מנחש ולא ״מבין מה התכוונת״. צריך להגיד לו כל צעד: ״פתח את הצנצנת. קח סכין. הכנס את הסכין לצנצנת. הוצא כמות קטנה. קח פרוסת לחם אחת. מרח...״. Programming (תכנות) זו האומנות לפרק בעיה גדולה לצעדים קטנים ומדויקים.

ההוראות שאתה כותב נקראות Code (קוד), ואוסף של קוד שעושה משהו שלם נקרא Program (תוכנית). מי שכותב קוד נקרא מתכנת, או באנגלית Developer (מפתח) או Programmer.

אלגוריתם: המתכון

Algorithm (אלגוריתם) הוא רשימת צעדים לפתרון בעיה. מתכון לעוגה הוא אלגוריתם. ההוראות להרכבת לגו הן אלגוריתם. הדרך שבה אתה מחפש מילה במילון (פותח באמצע, בודק אם המילה לפני או אחרי, וממשיך רק בחצי הנכון) היא אלגוריתם מפורסם בשם חיפוש בינארי.

לפני שכותבים קוד, מתכנתים טובים חושבים על האלגוריתם. הרבה פעמים כותבים אותו קודם בPseudocode (פסאודו-קוד, ״קוד מדומה״): הוראות בשפה רגילה שנראות כמו קוד. למשל:

כל עוד השחקן חי:
    קרא מה השחקן לחץ במקלדת
    הזז את השחקן
    אם השחקן נוגע במטבע:
        הוסף 10 נקודות
    אם השחקן נוגע באויב:
        הורד חיים
    צייר את כל המסך

הדבר הזה, אגב, הוא הלב של כל משחק מחשב בעולם. נחזור אליו בפרק המשחקים.

שלושה כלי-על של כל אלגוריתם

  • רצף: לעשות דברים אחד אחרי השני, לפי הסדר.
  • תנאי: ״אם... אז... אחרת...״. לקבל החלטות.
  • לולאה: לחזור על משהו כמה פעמים, או כל עוד משהו נכון.

עם שלושת הדברים האלה אפשר, תיאורטית, לכתוב כל תוכנה שקיימת. נסה עכשיו לתכנת רובוט:

שמת לב? כשהרובוט נתקע, היית צריך למצוא איפה הטעות בתוכנית ולתקן. טעות בקוד נקראת Bug (באג, ״חרק״). השם מגיע מ-1947, כשמצאו עש אמיתי תקוע בתוך מחשב ענק שלא עבד. תהליך מציאת ותיקון באגים נקרא Debugging (דיבאגינג, ניפוי באגים). מתכנתים מבלים בזה חלק גדול מהזמן, וזה נורמלי לגמרי.

אלגוריתם טוב לעומת אלגוריתם גרוע

לאותה בעיה יכולים להיות כמה פתרונות, וחלקם מהירים פי אלפים מאחרים. דוגמה: יש לך 1,000 קלפים מעורבבים ואתה צריך לסדר אותם. דרך אחת היא להשוות כל זוג שכנים ולהחליף אם צריך, שוב ושוב. דרך אחרת היא לבחור קלף ״ציר״, לחלק את כל הקלפים לקטנים ממנו ולגדולים ממנו, ולחזור על זה בכל חצי. נסה את שתיהן:

עם 32 מספרים ההבדל נראה קטן. אבל עם מיליון מספרים, מיון בועות צריך בערך חצי טריליון השוואות, ומיון מהיר צריך בערך 20 מיליון. זה ההבדל בין שנייה לשבוע. חברות כמו גוגל מעסיקות אנשים שכל מה שהם עושים זה למצוא אלגוריתמים מהירים יותר. בשפה של מתכנתים, מודדים את זה ב-Big O.

שפות תכנות

המחשב מבין רק שפת מכונה (אפסים ואחדים). בני אדם לא יכולים לכתוב ככה תוכנות גדולות. לכן המציאו Programming Language (שפת תכנות): שפה עם מילים ״אנושיות״ וחוקים מדויקים, שתוכנה מיוחדת מתרגמת למחשב.

הנה אותו רעיון (״הדפס שלום 5 פעמים״) בכמה רמות:

; Assembly — שפה ״נמוכה״, כמעט שפת מכונה
    mov ecx, 5
loop_start:
    push ecx
    call print_hello
    pop ecx
    dec ecx
    jnz loop_start

# Python — שפה ״גבוהה״, קרובה לאנגלית
for i in range(5):
    print("שלום")

// JavaScript
for (let i = 0; i < 5; i++) {
  console.log("שלום");
}

שפה נמוכה (Low-level) קרובה למה שהמחשב עושה באמת: מהירה מאוד, אבל קשה לכתוב בה. שפה גבוהה (High-level) קרובה לשפת בני אדם: קלה יותר, והמחשב עושה בשבילך הרבה עבודה.

מי מתרגם? קומפיילר ואינטרפרטר

יש שתי דרכים לתרגם שפת תכנות לשפת מכונה:

  • Compiler (מהדר, קומפיילר): מתרגם את כל התוכנית מראש, פעם אחת, לקובץ שהמחשב מריץ ישירות. כמו לתרגם ספר שלם לפני שנותנים אותו לקורא. מהיר מאוד בזמן הריצה. דוגמאות: C, C++, Rust, Go. המשחקים הגדולים (כולל GTA) כתובים בעיקר ב-C++ מהסיבה הזאת.
  • Interpreter (מפרש, אינטרפרטר): מתרגם ומריץ שורה אחרי שורה, תוך כדי. כמו מתורגמן סימולטני בכנס. גמיש ונוח ללמידה. דוגמאות: Python, JavaScript (שהיום בפועל גם מתורגמת תוך כדי ריצה בשיטה חכמה בשם JIT).

תחביר: הדקדוק של הקוד

לכל שפה יש Syntax (תחביר): חוקי כתיבה. בעברית, אם תשכח נקודה בסוף משפט, כולם עדיין יבינו. בתכנות, אם תשכח סוגריים אחד, התוכנית לא תרוץ בכלל ותקבל שגיאת תחביר (Syntax Error). זה מתסכל בהתחלה, אבל אחרי כמה שבועות העיניים שלך ילמדו לראות את זה אוטומטית. יש גם שגיאות לוגיות: הקוד רץ, אבל עושה משהו אחר ממה שרצית. אלה יותר קשות למציאה.

ההמלצה שלנו: התחל ב-JavaScript

למה? (1) היא רצה בכל דפדפן, בלי להתקין כלום. (2) איתה תבנה אתרים, אפליקציות ומשחקים, כך שתראה תוצאות מהר. (3) היא אחת השפות הכי מבוקשות בעבודה. (4) אחרי שתדע שפה אחת טוב, השפה השנייה קלה פי כמה, כי הרעיונות (משתנים, תנאים, לולאות, פונקציות) זהים בכל השפות. בהמשך, כשתגיע למשחקי תלת-ממד, תלמד C# (ל-Unity) או GDScript (ל-Godot), ואם תרצה ללכת עד הסוף, C++ (ל-Unreal).
